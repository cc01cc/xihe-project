# XH 常驻团队角色化（正式）

> 2026-11-09 由试行转正式（用户裁定）。方法层与 XH 实例参数合一，本文件是**唯一流程正文**；XH 实例参数（成员映射、lane 槽、资源实测值）以 `one/internal/A03-xihe/docs/team-roster.md` 为参考快照，二者冲突以本文件为准。

## 1 角色分层（最小可用 3，常驻 6）

| 角色 | 数量 | 职责 | 不可做 |
| --- | --- | --- | --- |
| `verify` | 1 | 读 diff、跑 L0/L1/L2 门集、核证据链、判「能否合并」、执行验证窗（book→门集→release） | 不改产品代码（缺陷只建卡）；不接管实施槽 |
| `dev-A` / `dev-B` | 2 | 在 Lead 指定槽位施工、分支内 commit、L0 自验 | 不碰验证槽/证据栈；不直提 develop；不同时编译 |
| `ops` | 1 | 文档/工具外围、台账审计补录、构建根与测量值班 | 不改产品代码；不跑编译 |
| `research-A` / `research-B` | 2 | A=调研评估（官方文档/源码核对、方案对比）；B=只读审计（代码/契约/证据链） | 不改任何可用文件；不跑编译/建栈；B 连正文也不写 |

`research` 为低资源常驻位：有活长跑、无活可回收为按需。

## 2 并行上限（XH 实测，2026-11-08）

两条独立上限，不要混：

1. **容器内存**：Docker VM 可用 ≈7.9 GiB ÷ 2 GiB/栈 ⇒ **≈3 栈**（dev 2 + 验证 1）；测量窗再占 1 隔离栈 ⇒ 测量期 dev 只留 1 槽。`[实测]`
2. **host 编译并发 ≤2**：与容器内存无关，被抢的是墙钟与测量可比性（maven 冷 9.3s/增量 8.3s、cargo 冷 66s/增量 4.4s ⇒ 编译本身便宜）。`[实测]`

```powershell
(Get-CimInstance Win32_Process -Filter "Name='java.exe' OR Name='cargo.exe' OR Name='rustc.exe'" |
  Where-Object { $_.CommandLine -match 'mvn|spring-boot|cargo|rustc' }).Count   # 应 ≤2；测量窗内 ≤1
```

**并行度三算**：写面冲突（同一测试基座/同一配置文件必须串行，产品码可并行）→ 编译位（≤2，空着先补位）→ 栈内存。把「测试基座串行」误推成「整体串行」会让编译位空转（2026-11-08 白等 25min 实证）。

## 3 命名约定（2026-11-09 用户指正后定）

- **成员名 = 角色名**，小写 kebab-case：`verify` / `dev-a` / `dev-b` / `ops` / `research-a` / `research-b`；多实例加序号（`dev-a2`）。
- **禁止任务码当成员名**（`impl-<PLAN>-<槽位>` 形态）：GUI 会话列表按成员名展示，任务码无法映射角色。
- 已建成员名不合约定：**不重建**（打断在飞任务），登记「旧名→角色」映射，闭环后回收再按角色名建。

## 4 测量窗值班时间线

| 时刻 | 动作 |
| --- | --- |
| T-15 | 通知全部成员准备测量；值班位（`ops`）收尾当前卡 |
| 窗口开始 | 测量独占 run：独立构建根 + 独占端口段，不与任何 run 并行 |
| 窗内 | 只 `ops`（值班）+ `verify`（读数）可动；`dev` 不开新长构建；`research` 只做网络/文档调研 |
| 窗口结束 | 释放构建根/端口；`ops` 交回外围卡；**提前跑完即收窗，不得用余时塞功能 run** |

## 5 生命周期

- **idle 判据**：连续 2 轮 idle 且名下无 `in_progress` 卡 ⇒ 不主动派活（inactive ≠ 缺活）。
- **回收**：某角色连续 2 个工作日无卡 ⇒ 常驻位降为按需，登记（回收≠解雇）。
- **临时席**：单次长链路任务可建临时席（如测量重跑），但必须**先登记**（角色/名称/职责/生命周期），任务闭环即回收，不转常驻。
- **建成员前三查**：①复用 inactive 常驻位 ②临时席是否登记 ③是否满足「多轮续跑 / 需反复调度 / 长期持有写面」——三条都不满足走一次性 `subagent`（workspace `.agents/skills/subagent-orchestration/references/dsh-team.md` §5 八维对比表）。

## 6 交接联动（防继任漏建成员）

- 交接档必须有「团队重建」章节：列 roster 表（角色/成员名/状态）**或**写明「本会话不建常驻：<理由>」。
- 契约落点：`scripts/handoff-contract.json` 的 `team_rebuild` 必检章节（`any_of` 标题 + `must_reference` → roster + 三列表 + 例外句豁免），validator 通用实现零 section-id 硬编码；selftest 23/23。`[实测]` 2026-11-09：11-09 交接档 12/12 通过却漏建 6 常驻 ⇒ 加章节后同档 12/13 FAIL（门按预期拦截）。
- **根因教训**：方法论与 roster 文档都存在，但**交接契约不检查** ⇒ 继任会话不读它们。文档存在 ≠ 流程会执行，检查点必须做进自动校验。

## 7 常见反例（均付过代价）

| 反例 | 代价 |
| --- | --- |
| 6 常驻全起但无活可派 | 空转 + 占满 8 名额（subagent 被拒） |
| 一次性 subagent 跑等待型长任务 | 后台 job 完成不唤醒 ⇒ 停摆 15min（2026-11-09 D-762③） |
| 任务码当成员名 | GUI 一排名字无法对应角色 |
| 不建卡只发消息派活 | 面板空、继任无从追踪（任务板是唯一事实源） |
| 交接档只写授权/队列/定时器 | 继任漏建成员，全部任务退回 one-shot |
