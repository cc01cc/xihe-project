# UI 审阅维度速查（截图审阅用）

> 判据正文见 `DEV-011` §11；标准来源见 `DEV-012`「标准与规范」。本文件是**执行速查**，不重述正文。
> 维护纪律：判据没写清 ⇒ 回写 `DEV-011` §11；实现偏离 ⇒ 转卡。本文件随判据变化更新。

## 六维（每维只问一句「截图能不能判」）

| 维 | 一句话判据 | 截图怎么判 |
| --- | --- | --- |
| A 反馈 | 每个可点元素点下去有可观察结果 | 点一次，1 帧内应有状态变化（spin/文案/跳转） |
| B 一致性 | 同语义同图标同尺寸同格式 | 跨两页对比同一动作 |
| C 层级排版 | 三级字阶可分、行高 ≥1.5、数字等宽 | 眯眼看层级是否清楚 |
| D 无障碍 | 对比 4.5:1、焦点可见、图标有 aria-label、目标 ≥24px | 灰度化截图 + Tab 走一遍 |
| E 内容真实 | 计数与可见项一致、空态有出口、无硬编码 | 数一遍页面上实际有几项 |
| F 布局自适应 | 三档视口无溢出、折叠有回入口 | 1600/1280/390 各拍一张 |

## 三档分级

- **P0 阻断**：点不动 / 数据矛盾 / 路径不可达 —— 当天转卡。
- **P1 明显**：层级、一致性、无障碍 AA 违例 —— 当批转卡。
- **P2 打磨**：间距、字重、微差 —— 攒批，不阻塞。

## 拍图规则

```text
1. 钉在 commit 上（脏树不许拍），否则图对不上代码；
2. 视口 1600×1000 主用 + 1920×1080 / 390×844 各一轮；
3. 数据要真实（mock 先跑通读写），占位符会掩盖溢出与截断；
4. 图放 .tmp/<批次>/，报告只给路径与结论，不把图塞进文档；
5. 每页结论写「维 + 元素 + 现象 + 判据 + 档位」；写不出判据 ⇒ 判据缺失，回写 DEV-011。
```

## 常见反例（实际审阅攒的，继续加）

- 计数文案「本域 N 项配置」但页面 0 字段（E：计数口径 ≠ 可见项）。
- 同一动作两个入口（rail 有入口 + 页内又有返回链接）（B + A）。
- 缺口项与真链接外观相同、只靠小徽标区分（B / A：不可点却像可点）。
- 辅助说明文字 12–13px 中文、长句行距紧（C）。
