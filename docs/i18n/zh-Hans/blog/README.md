# 开发博客

这里放**叙事型**文章：为什么这么设计、踩了什么坑、怎么权衡。与 `DEV-0xx` 是两种体裁，别混用。

| | `DEV-0xx` | `blog/` |
|---|---|---|
| 体裁 | 工具书（查命令 / 查判据 / 查已知问题） | 叙事（讲过程 / 讲取舍 / 讲事故） |
| 编号 | 续接编号、中英对照、进文档站导航 | **日期命名**、不占 DEV 编号 |
| 读者 | 需要「怎么做」的人 | 需要「为什么」的人 |

## 写作规则

1. 文件名 `YYYY-MM-DD-<slug>.md`，例 `2026-11-09-three-false-signals.md`
2. **结论前置**：第一段就说清这篇讲什么、结论是什么
3. **证据可验**：`file:line`、命令、实测数字；**未实测的数字一律标注"未实测"**，不许编
4. **不复制工具书内容**：命令与判据写进 `DEV-0xx`，博客只引用
5. 涉及内部失误的，写清「当时的判断、依据、错在哪、改了什么规则」，不写成宣传稿
